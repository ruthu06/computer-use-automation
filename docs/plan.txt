Computer-Use Automation System
Implementation plan for the interface.ai take-home assignment. Date: October 7, 2026 Status: Plan only. Implementation has not started.
In one sentence: Claude looks at a real local banking website once, figures out how to complete a task, and we save those steps as a reusable recipe that Playwright can repeat later without AI.
1. What we are building
A bank's AI agent needs hands to operate old internal applications that have no API. The only way in is to drive the screen the way a person would. This system does that in two phases:
	•	Discovery (once): Claude looks at the screen, decides the next click or keystroke, and repeats until the goal is done.
	•	Replay (many times): The successful run is saved as a structured recipe, called an artifact. Later runs follow that recipe with no AI in the decision loop.
The assignment's rule: The model discovers. The artifact becomes a reusable capability. Deterministic replay is how the agent invokes it in production.

4. How a run works
	•	A caller sends a goal, such as: "Log in, open a new savings account, and return the new account number and displayed balance."
	•	Playwright opens the local ParaBank page and captures what is on screen.
	•	Sensitive values are redacted, then the observation is sent to Claude.
	•	Claude returns exactly one action: click, type, select, read, wait, complete, or request a human.
	•	A policy check decides whether that action is allowed.
	•	Playwright performs the action on the same browser session.
	•	The loop repeats until success, a known business outcome, a hard failure, or a stop condition.
	•	A successful discovery is compiled into a versioned JSON artifact.
	•	Later, replay loads that artifact and repeats the steps with no Claude calls.
5. What each part does
5.1 ParaBank target
	•	Start a pinned official image and expose it only on localhost.
	•	Reset the container or register a uniquely named synthetic user.
	•	Primary flow: login, open a new savings account, return the account number and balance.
	•	Claude sees only the live screen. It does not receive source code or a prewritten click path.
	•	Error cases: bad login as a business outcome; one slowed page as recoverable; one missing control as a hard failure.
5.2 Surface
One interface: observe, act, and wait. The web version uses Playwright. The artifact and replay engine do not know they are talking to a browser, so a desktop driver could be added later.
5.3 Discovery loop
Each turn is observe, redact, ask Claude, check policy, act, and log. Stop on a verified checkpoint, too many steps, a timeout, or a repeated screen. Claude may not leave the allowlist, call ParaBank's API, or submit a risky final action without approval.
5.4 Artifact
The JSON recipe contains identity and version, typed inputs, typed outputs, ordered steps, a success condition, and redaction rules. Each step tries locators in this order: accessible role and name, visible label, structural path, then screenshot coordinates.
5.5 Replay
Result
Example
What happens
Success
New savings account opened
Return the declared outputs.
Business outcome
Invalid login
Return it as a legitimate answer, not a crash.
Recoverable
Page is temporarily slow
Wait or retry, then continue.
Hard failure
Expected control never appears
Stop and report the step, expectation, and observation.
5.6 Safety
	•	Allowlist of addresses, routes, and action types, enforced during discovery and replay.
	•	The click that opens an account pauses for explicit human approval.
	•	Passwords, tokens, and personal data are redacted from artifacts and logs.
5.7 Evidence
Every run writes a structured log. Failures also save a screenshot and page snapshot under /evidence/. The submission includes discovery, successful replay, and one error replay.
5.8 Human takeover
	•	Create an intervention request with the step, screenshot, and reason.
	•	Release the same live browser to the person.
	•	Record what the person did.
	•	Hand control back and continue.
Session states: AUTOMATION, PAUSED, HUMAN, RESUMING.
5.9 API
	•	POST /discover
	•	GET /capabilities and GET /capabilities/{id}
	•	POST /capabilities/{id}/replay
	•	POST /sessions/{id}/takeover and POST /sessions/{id}/resume
6. What we will not build
	•	A custom banking website.
	•	A full operator console. Control transfer is real; the console stays minimal.
	•	A desktop driver. The design leaves room for one.
	•	Queues, clusters, or multi-tenant infrastructure.
	•	Optional stretch goals, until the required slice is done.

9. Downloads and setup
	•	Java 21 JDK. Eclipse Temurin 21 is recommended. Check java -version and javac -version.
	•	Docker Desktop for Windows with WSL 2 and Compose.
	•	Git for Windows.
	•	Anthropic API key, stored as ANTHROPIC_API_KEY and never committed.
	•	Cursor extensions: Extension Pack for Java, Spring Boot Extension Pack, Docker, and YAML.
	•	A GitHub account that can create a public repository.
Do not install Node.js, a database, ParaBank source code, or Kubernetes. Maven Wrapper and Playwright's browser are added with the project.
